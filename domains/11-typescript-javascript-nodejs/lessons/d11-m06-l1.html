Node.js Runtime
基礎Lesson

ECMAScript、TypeScriptの型システム、V8、libuv、Node.js APIを統合して、正しく高速なサーバとツールを作る。 このLessonでは「概念、語彙、前提、最小モデルを構築する」ことに集中します。

1. なぜ重要か

Node.js Runtimeは、TypeScript・JavaScript・Node.jsにおいて「Nodeの性能とブロッキング原因を説明できる」ための中核テーマです。実務では単独で現れるより、周辺の概念や制約と組み合わさって現れます。そのため、用語の定義だけでなく、どの条件で使い、何を保証し、どこで破綻するかを一つのモデルとして理解します。

このLessonでは、V8、libuv、event loop、thread poolを同じ地図上に配置します。専門家は「知っている技術の数」ではなく、問題を正しい抽象度へ置き、必要な証拠を集め、複数案から条件付きで判断できる人です。

講義本文: Node.jsはJavaScript実行をV8、platform非依存の非同期I/Oとevent loopをlibuvへ依存します。network I/Oの多くはOSの readiness notificationを使い、file system、一部crypto/DNSなどはlibuv thread poolへ委譲されます。JavaScript callback自体は通常main threadで動くため、長いCPU処理、巨大JSON、同期API、microtaskの連鎖はevent loopを停止させます。

2. 中核概念

V8

Googleが開発するJavaScript/WebAssembly engineで、parser、bytecode interpreter、JIT compiler、garbage collectorを含みます。Node.jsではJavaScriptの実行とheap管理を担います。 最小例を手で追い、入力・状態・出力を確認してください。

libuv

Node.jsが利用するcross-platform I/O libraryです。event loop、network readiness、timer、thread pool、process・signal処理をOS差から抽象化します。 最小例を手で追い、入力・状態・出力を確認してください。

event loop

readyになったI/O、timer、callbackをphaseごとに取り出して実行するloopです。callbackが長時間CPUを占有すると、他requestの処理開始が遅れます。 最小例を手で追い、入力・状態・出力を確認してください。

thread pool

複数worker threadへblockingまたはCPU処理を割り当てる仕組みです。queueが詰まると非同期APIでも待ち時間が増えます。 最小例を手で追い、入力・状態・出力を確認してください。

4. 学習・実装手順

  1. 用語を自分の言葉で定義し、似た用語との差分を書く。

  4. 予測との差分を「前提の不足」「観測の不足」「理解の誤り」に分類する。

最小実験

type NodejsRuntimeState = {
  topic: string;
  status: 'new' | 'validated';
};

function validate(input: unknown): NodejsRuntimeState {
  if (typeof input !== 'object' || input === null) {
    throw new TypeError('invalid input');
  }
  return { topic: 'V8', status: 'validated' };
}

5. 設計判断とトレードオフ

基礎段階では網羅性より、概念間の境界を正確にすることを優先します。便利な比喩は入口として使えますが、比喩が成立しない条件も必ず確認してください。

観点確認する問い
正しさどの不変条件を守り、どの入力・並行性・障害まで保証するか。
性能時間、空間、I/O、ネットワーク、待ち行列のどこが上限になるか。
安全性悪意ある入力、権限境界、情報漏えい、誤操作にどう耐えるか。
変更容易性要件変更時にどの境界まで影響し、互換性をどう維持するか。
運用性失敗をどう検知し、誰が何を見て、どの手順で復旧するか。

6. 典型的な失敗

  • V8とlibuvを同じものとして扱い、境界条件を失う。
  • 小さな成功例だけで一般化し、入力規模・並行性・障害時に破綻する。
  • 結果だけを確認し、途中状態や観測証拠を残さない。
  • 採用した方式の前提条件と、撤退条件を記録しない。
