高度なTypeScript

ECMAScript、TypeScriptの型システム、V8、libuv、Node.js APIを統合して、正しく高速なサーバとツールを作る。 このLessonでは「概念、語彙、前提、最小モデルを構築する」ことに集中します。

1. なぜ重要か

高度なTypeScriptは、TypeScript・JavaScript・Node.jsにおいて「再利用可能な型レベルAPIを構築できる」ための中核テーマです。実務では単独で現れるより、周辺の概念や制約と組み合わさって現れます。そのため、用語の定義だけでなく、どの条件で使い、何を保証し、どこで破綻するかを一つのモデルとして理解します。

このLessonでは、conditional type、mapped type、infer、template literal typeを同じ地図上に配置します。専門家は「知っている技術の数」ではなく、問題を正しい抽象度へ置き、必要な証拠を集め、複数案から条件付きで判断できる人です。

講義本文: conditional typeは型関係に応じて結果型を分岐し、mapped typeはkey集合を反復してpropertyを変換します。inferはconditional type内で部分型を抽出し、template literal typeは文字列patternを型として合成します。強力な型計算はAPIの誤用を減らせますが、compile時間、error可読性、再帰深度を悪化させるため、型の目的と公開範囲を制限します。

2. 中核概念

conditional type

T extends U ? X : Y のように型関係を条件として結果型を選ぶTypeScriptの型演算です。unionへ分配される条件も理解が必要です。 最小例を手で追い、入力・状態・出力を確認してください。

mapped type

key集合を反復して各propertyの型やreadonly/optional属性を変換するTypeScriptの型演算です。 最小例を手で追い、入力・状態・出力を確認してください。

infer

conditional typeのpattern内で型の一部分を新しい型変数として取り出すTypeScript keywordです。 最小例を手で追い、入力・状態・出力を確認してください。

template literal type

「template literal type」は、高度なTypeScriptを理解するための基本語彙です。定義だけを覚えるのではなく、何を区別し、どの条件で成立し、どの現象を説明するための概念かを確認します。TypeScript・JavaScript・Node.jsでは、入力・状態・変換・出力のどこに位置するかを図にすると理解が安定します。

3. メンタルモデル

  1. 高度なTypeScriptを「入力 → 状態 → 規則 → 出力」の流れで整理する。
  2. 各概念（conditional type、mapped type、infer、template literal type）の違いを一文で説明する。
  3. 小さな具体例を手作業で追跡し、用語と挙動を結びつける。
  4. 成立条件と、成立しない反例を一つずつ用意する。
注意: 図や比喩は理解を助けますが、保証ではありません。境界条件と反例を一緒に持つことで、比喩の誤用を防げます。

4. 学習・実装手順

  1. 用語を自分の言葉で定義し、似た用語との差分を書く。
  2. 最小の入力例を作り、状態がどう変化するかを追う。
  3. 結果を予測してからコード・計算・観測で確かめる。
  4. 予測との差分を「前提の不足」「観測の不足」「理解の誤り」に分類する。

5. 設計判断とトレードオフ

基礎段階では網羅性より、概念間の境界を正確にすることを優先します。便利な比喩は入口として使えますが、比喩が成立しない条件も必ず確認してください。

観点確認する問い
正しさどの不変条件を守り、どの入力・並行性・障害まで保証するか。
性能時間、空間、I/O、ネットワーク、待ち行列のどこが上限になるか。
安全性悪意ある入力、権限境界、情報漏えい、誤操作にどう耐えるか。
変更容易性要件変更時にどの境界まで影響し、互換性をどう維持するか。
運用性失敗をどう検知し、誰が何を見て、どの手順で復旧するか。

6. 典型的な失敗

  • conditional typeとmapped typeを同じものとして扱い、境界条件を失う。
  • 小さな成功例だけで一般化し、入力規模・並行性・障害時に破綻する。
  • 結果だけを確認し、途中状態や観測証拠を残さない。
  • 採用した方式の前提条件と、撤退条件を記録しない。
