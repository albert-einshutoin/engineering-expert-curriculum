中間表現
基礎Lesson

ソースコードが字句解析、構文解析、最適化、コード生成、実行時管理を経て動く全過程を実装目線で学ぶ。 このLessonでは「概念、語彙、前提、最小モデルを構築する」ことに集中します。

1. なぜ重要か

中間表現は、Compiler・Interpreter・Runtimeにおいて「最適化しやすい表現へ変換できる」ための中核テーマです。実務では単独で現れるより、周辺の概念や制約と組み合わさって現れます。そのため、用語の定義だけでなく、どの条件で使い、何を保証し、どこで破綻するかを一つのモデルとして理解します。

このLessonでは、three-address code、SSA、CFG、data-flowを同じ地図上に配置します。専門家は「知っている技術の数」ではなく、問題を正しい抽象度へ置き、必要な証拠を集め、複数案から条件付きで判断できる人です。

講義本文: IRはソース言語と機械語の間に置く、解析・変換しやすい表現です。CFGは基本ブロック間の制御遷移を表し、SSAでは各変数が一度だけ代入されるため定義使用関係が明確になります。IRの抽象度を複数段階に分けると、高水準の意味最適化と低水準の機械最適化を両立できます。

3. メンタルモデル

  1. 中間表現を「入力 → 状態 → 規則 → 出力」の流れで整理する。
  2. 各概念（three-address code、SSA、CFG、data-flow）の違いを一文で説明する。
  3. 小さな具体例を手作業で追跡し、用語と挙動を結びつける。
  4. 成立条件と、成立しない反例を一つずつ用意する。
注意: 図や比喩は理解を助けますが、保証ではありません。境界条件と反例を一緒に持つことで、比喩の誤用を防げます。

4. 学習・実装手順

  1. 用語を自分の言葉で定義し、似た用語との差分を書く。
  2. 最小の入力例を作り、状態がどう変化するかを追う。
  3. 結果を予測してからコード・計算・観測で確かめる。
  4. 予測との差分を「前提の不足」「観測の不足」「理解の誤り」に分類する。

5. 設計判断とトレードオフ

基礎段階では網羅性より、概念間の境界を正確にすることを優先します。便利な比喩は入口として使えますが、比喩が成立しない条件も必ず確認してください。

観点確認する問い
正しさどの不変条件を守り、どの入力・並行性・障害まで保証するか。
性能時間、空間、I/O、ネットワーク、待ち行列のどこが上限になるか。
安全性悪意ある入力、権限境界、情報漏えい、誤操作にどう耐えるか。
変更容易性要件変更時にどの境界まで影響し、互換性をどう維持するか。
運用性失敗をどう検知し、誰が何を見て、どの手順で復旧するか。

6. 典型的な失敗

  • three-address codeとSSAを同じものとして扱い、境界条件を失う。
  • 小さな成功例だけで一般化し、入力規模・並行性・障害時に破綻する。
  • 結果だけを確認し、途中状態や観測証拠を残さない。
  • 採用した方式の前提条件と、撤退条件を記録しない。

7. 演習

  2. 中間表現の最小例を紙またはコードで作り、入力から出力までを追跡する。
  3. 意図的に誤った説明を一つ書き、どこが誤りかを根拠付きで訂正する。

8. 理解度チェック

ソースコードが字句解析、構文解析、最適化、コード生成、実行時管理を経て動く全過程を実装目線で学ぶ。の中で、特に「最適化しやすい表現へ変換できる」ために使います。

three-address codeとSSAの違いは何ですか？

定義、入力、出力、成立条件、失敗条件の5点で比較してください。用語の言い換えだけではなく、同じ例へ適用したときの挙動差を示せれば十分です。

理解したと判断する最小の証拠は何ですか？

説明、具体例、反例、再現可能な確認の4つが揃っていることです。
