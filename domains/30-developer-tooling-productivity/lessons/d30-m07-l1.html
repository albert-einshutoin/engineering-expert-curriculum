CLI・TUI Design
基礎Lesson

IDE、LSP、デバッガ、静的解析、コード生成、CLI、パッケージ、開発環境を理解し、開発者の認知負荷を下げる。 このLessonでは「概念、語彙、前提、最小モデルを構築する」ことに集中します。

1. なぜ重要か

CLI・TUI Designは、Developer Tooling・開発者生産性において「自動化と人間操作の双方に強いツールを作れる」ための中核テーマです。実務では単独で現れるより、周辺の概念や制約と組み合わさって現れます。そのため、用語の定義だけでなく、どの条件で使い、何を保証し、どこで破綻するかを一つのモデルとして理解します。

このLessonでは、argument parser、stdin・stdout、exit code、interactive UXを同じ地図上に配置します。専門家は「知っている技術の数」ではなく、問題を正しい抽象度へ置き、必要な証拠を集め、複数案から条件付きで判断できる人です。

講義本文: CLIはstdin/stdout/stderrとexit codeを安定contractにし、human向け色表示とmachine向けJSONを分けます。subcommand、flag、environment、configのprecedenceを一貫させます。TUI/interactive modeでもnon-interactive、dry-run、confirm、cancel、signal、progress、idempotencyを維持します。

3. メンタルモデル

  1. CLI・TUI Designを「入力 → 状態 → 規則 → 出力」の流れで整理する。
  2. 各概念（argument parser、stdin・stdout、exit code、interactive UX）の違いを一文で説明する。
  3. 小さな具体例を手作業で追跡し、用語と挙動を結びつける。
  4. 成立条件と、成立しない反例を一つずつ用意する。
注意: 図や比喩は理解を助けますが、保証ではありません。境界条件と反例を一緒に持つことで、比喩の誤用を防げます。

4. 学習・実装手順

  1. 用語を自分の言葉で定義し、似た用語との差分を書く。
  2. 最小の入力例を作り、状態がどう変化するかを追う。
  3. 結果を予測してからコード・計算・観測で確かめる。
  4. 予測との差分を「前提の不足」「観測の不足」「理解の誤り」に分類する。

最小実験

CONTEXT: Developer Tooling・開発者生産性

INPUT: argument parser
CONSTRAINT: stdin・stdout
PROCESS:
  1. Define the invariant.
  2. Observe the mechanism.
  3. Introduce one controlled failure.
  4. Record evidence.
OUTPUT: A decision that another engineer can verify.

コードは完成品ではなく、観測可能な最小実験の出発点です。自分の環境で動かし、前提と結果を記録してください。

5. 設計判断とトレードオフ

基礎段階では網羅性より、概念間の境界を正確にすることを優先します。便利な比喩は入口として使えますが、比喩が成立しない条件も必ず確認してください。

観点確認する問い
正しさどの不変条件を守り、どの入力・並行性・障害まで保証するか。
性能時間、空間、I/O、ネットワーク、待ち行列のどこが上限になるか。
安全性悪意ある入力、権限境界、情報漏えい、誤操作にどう耐えるか。
変更容易性要件変更時にどの境界まで影響し、互換性をどう維持するか。
運用性失敗をどう検知し、誰が何を見て、どの手順で復旧するか。

6. 典型的な失敗

  • argument parserとstdin・stdoutを同じものとして扱い、境界条件を失う。
  • 小さな成功例だけで一般化し、入力規模・並行性・障害時に破綻する。
  • 結果だけを確認し、途中状態や観測証拠を残さない。
  • 採用した方式の前提条件と、撤退条件を記録しない。

7. 演習

  1. argument parser、stdin・stdout、exit codeをそれぞれ120字以内で定義し、違いを表にする。
  2. CLI・TUI Designの最小例を紙またはコードで作り、入力から出力までを追跡する。
  3. 意図的に誤った説明を一つ書き、どこが誤りかを根拠付きで訂正する。
Expert Challenge: CLI・TUI Designについて、初学者が混同しやすい2概念を選び、図と100字以内の説明で区別してください。
