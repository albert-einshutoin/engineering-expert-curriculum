Load Test・Capacity
基礎Lesson

レイテンシ、スループット、CPU、メモリ、I/Oを測定し、モデル・証拠・実験で性能を改善する。 このLessonでは「概念、語彙、前提、最小モデルを構築する」ことに集中します。

このLessonの到達目標

  • 本番に近い負荷で限界と安全域を測れる
  • workload model、ramp・soak・spike、bottleneck、headroomの関係を説明できる

1. なぜ重要か

Load Test・Capacityは、Performance Engineeringにおいて「本番に近い負荷で限界と安全域を測れる」ための中核テーマです。実務では単独で現れるより、周辺の概念や制約と組み合わさって現れます。そのため、用語の定義だけでなく、どの条件で使い、何を保証し、どこで破綻するかを一つのモデルとして理解します。

このLessonでは、workload model、ramp・soak・spike、bottleneck、headroomを同じ地図上に配置します。専門家は「知っている技術の数」ではなく、問題を正しい抽象度へ置き、必要な証拠を集め、複数案から条件付きで判断できる人です。

講義本文: workload modelはrequest mix、arrival pattern、session、data size、cache、dependencyを本番に近づけます。rampで曲線、spikeで急増、soakでleak、stressでfailure modeを確認します。client側が目標rateを出せているか、coordinated omission、warm-up、autoscaling delay、recoveryを測ります。

3. メンタルモデル

  1. Load Test・Capacityを「入力 → 状態 → 規則 → 出力」の流れで整理する。
  2. 各概念（workload model、ramp・soak・spike、bottleneck、headroom）の違いを一文で説明する。
  3. 小さな具体例を手作業で追跡し、用語と挙動を結びつける。
  4. 成立条件と、成立しない反例を一つずつ用意する。
注意: 図や比喩は理解を助けますが、保証ではありません。境界条件と反例を一緒に持つことで、比喩の誤用を防げます。

4. 学習・実装手順

  1. 用語を自分の言葉で定義し、似た用語との差分を書く。
  2. 最小の入力例を作り、状態がどう変化するかを追う。
  3. 結果を予測してからコード・計算・観測で確かめる。
  4. 予測との差分を「前提の不足」「観測の不足」「理解の誤り」に分類する。

最小実験

#!/usr/bin/env bash
set -euo pipefail

for run in $(seq 1 10); do
  /usr/bin/time -f '%e %M' ./target-workload \
    --topic 'workload model' --constraint 'ramp・soak・spike'
done

# Record environment, warm-up, percentile, and variance.

コードは完成品ではなく、観測可能な最小実験の出発点です。自分の環境で動かし、前提と結果を記録してください。

5. 設計判断とトレードオフ

基礎段階では網羅性より、概念間の境界を正確にすることを優先します。便利な比喩は入口として使えますが、比喩が成立しない条件も必ず確認してください。

観点確認する問い
正しさどの不変条件を守り、どの入力・並行性・障害まで保証するか。
性能時間、空間、I/O、ネットワーク、待ち行列のどこが上限になるか。
安全性悪意ある入力、権限境界、情報漏えい、誤操作にどう耐えるか。
変更容易性要件変更時にどの境界まで影響し、互換性をどう維持するか。
運用性失敗をどう検知し、誰が何を見て、どの手順で復旧するか。

6. 典型的な失敗

  • workload modelとramp・soak・spikeを同じものとして扱い、境界条件を失う。
  • 小さな成功例だけで一般化し、入力規模・並行性・障害時に破綻する。
  • 結果だけを確認し、途中状態や観測証拠を残さない。
  • 採用した方式の前提条件と、撤退条件を記録しない。

  2. Load Test・Capacityの最小例を紙またはコードで作り、入力から出力までを追跡する。

8. 理解度チェック

Load Test・Capacityは何を解決するための概念群ですか？

レイテンシ、スループット、CPU、メモリ、I/Oを測定し、モデル・証拠・実験で性能を改善する。の中で、特に「本番に近い負荷で限界と安全域を測れる」ために使います。

workload modelとramp・soak・spikeの違いは何ですか？

定義、入力、出力、成立条件、失敗条件の5点で比較してください。用語の言い換えだけではなく、同じ例へ適用したときの挙動差を示せれば十分です。

理解したと判断する最小の証拠は何ですか？
